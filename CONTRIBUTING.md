# Contributing to DevLinks 💚

Thanks for helping out! We keep contributions small and friendly. Please follow these house rules — they make review fast and keep the project healthy.

## Workflow
1. **Find an issue** labelled `good first issue` or `help wanted`. Check it isn't already assigned or linked to a PR.
2. **Comment** to say you're taking it (optional but nice).
3. **Fork** the repo and **clone** your fork.
4. **Create a branch** — never work on `main`:
   ```
   fix/<issue-number>-short-description
   e.g. fix/1-heading-typo
   ```
5. **Make one scoped change.** One issue = one pull request. Do not bundle unrelated fixes.
6. **Commit** using [Conventional Commits](https://www.conventionalcommits.org/):
   ```
   fix: correct typo in main heading
   feat: add hover state to link buttons
   docs: clarify how to run locally
   ```
7. **Open a pull request**, fill in the template, and **link the issue** with `Fixes #<number>`.
8. Our review bot will check your PR and may **request changes** — that's normal! Address the comments, push again, and it will re-review.

## What makes a great PR
- Small and focused (a reviewer can understand it in one read).
- Linked to an issue.
- A clear "What & Why" in the description.
- Tested locally (you opened `index.html` and saw it works).

Welcome aboard — we're glad you're here! 🪺
